# 它会在你的机器与账号上碰什么

## 留在你机器上的东西

仓库包含项目源码、接口名称表、补丁与文档，许可证范围见 [LICENSE](../LICENSE)。不包含游戏、Steam 组件、SDK 或第三方运行时二进制。运行时从上游服务获取，本项目不提供镜像。

下载使用你已登录的 Steam，不接触密码。不打 Steam 客户端补丁，不改平台映射；入库使用所选账号的非 Steam 游戏快捷方式。检出反作弊就拒绝打包，风险资料不完整也会在下载和打包前停止。

主程序带 Steamworks DRM 包装（PE 节 `.bind`）的游戏，Wine 路线在打包前停下并说明原因：它需要同一前缀里运行中的 Windows 版 Steam，本工具不绕过 DRM。检查器出错也停止打包，旧覆盖开关不能放行。原生路线不运行这个 exe，只提示并继续（详见 [LEGAL.md](LEGAL.md)）。

单机游戏为兼容所需，可以修改你机器上的独立工作副本，Steam 原件保持不变。每个补丁须留存原件副本、记录输入与输出哈希，并提供不动存档的恢复路径；不得修改或绕过反作弊与 DRM，不分发改后游戏。详见[副本修改约定](架构.md#游戏工作副本与恢复)，现有路线尚未全部完成恢复验证。

## Steam 调试开关

客户端下载目前依赖 Steam 的本地调试端口。没开过的机器运行 `./bin/dryport steam-debug --enable`（或点 app 状态栏的按钮），经你确认后在 Steam 包内创建 Valve 自己的开关文件（空文件 `.cef-enable-remote-debugging`），包内其他东西一概不碰，之后重启一次 Steam。开关开着且 Steam 在跑期间，这台 Mac 上的任何程序都能经这个端口控制你的 Steam 客户端：装游戏时开，装完就关（`dryport steam-debug --disable`，然后重启 Steam）。

## Steam 桥

手工入口 `lib/steambridge/install-into-game.sh` 只接受生成的 Wine app 内的
`SN_GAMES/<name>.app/Contents/Resources/game` 目录，并核对 Wine 元数据与 appid。
游戏根目录可指向另一目录；解析后的根目录以下有链接，或 DLL 有硬链接，都会在启动 helper 或替换文件前被拒绝；不能直接接入原件目录。

桥让 Wine 里的 Windows 游戏使用你本机已登录的 Steam 身份与成就。默认不接，按游戏用 `dryport bridge enable <appid>` 打开，打开前会先讲清它做什么并要你确认。连接须在两秒总截止期内提交本次启动的随机令牌。令牌只验证持有者，不验证游戏进程身份；同用户隔离尚未建立，拿到令牌的其它程序也能使用 helper。联机、票据、道具面永远不转发。打开即意味着成就与统计会写入登录的这个账号；账号安全性未证实。

本机组装运行时也需要遵守游戏和引擎的适用条款，[授权边界](LEGAL.md#authorization-boundaries)中列出了仍待解决的问题。

helper 最多保留四个待认证连接和八个总连接，并行读取待认证令牌。认证、未完成的请求帧和阻塞的响应都有两秒总截止期；已经收完响应的客户端可空闲 30 秒，之后断开。假 API 测试要求合法客户端在三秒内收到 HELLO，覆盖三个静默客户端、二十个待认证连接、每 0.2 秒新增连接的持续流，以及已认证但不发送请求的客户端。这是被测 socket 等待的上限，不限制 Steam API 本身的执行时间，也不证明能抵御任意本机程序。游戏暂停 Steam 调用超过 30 秒时可能需要重连，仍须真游戏复核。
